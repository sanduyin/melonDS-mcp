# melonDS 金手指与普通存档

这套 MCP 是独立无头模拟器，不是附着到用户已经打开的 GUI。优先调用已连接的 MCP；若仅存在本机项目，可用它的 Python facade/同一 DLL，在独立进程中操作。不要因为工具未列出就替用户更改客户端配置。

## 确定范围与保护原档

- 只修改用户要求的字段。全图鉴不等于全员加入、全蓝图拥有或剧情通关；不要顺便改钱、招募标记或解锁结局。
- 明确选定 ROM 和普通 `.sav`。调用 `save_workspace_prepare` 创建新隔离目录，记录 ROM SHA256、游戏代码、修订号和原存档 SHA256，然后 `load_rom` 返回的副本路径。目录存在就另选目录，不覆盖它。
- 本核心自动读取 ROM 邻近同名 `.sav`，游戏保存和 `savestate_load` 都可能写回该路径。不要在唯一原件旁启动修改测试；不要把 `.mst` 等即时存档称为可携带普通存档。开始前清除本次子进程的 `MELONDS_MCP_ROM` 自动加载设置，避免意外载入原件。
- 用户未提供必要文件时说明缺少什么；不下载商业 ROM 来代替。

## 定位与验证

- 工具参数/限制看 [存档工具说明](../../../mcp/docs/SAVE_WORKFLOWS.md)。仅当游戏为《无限航路》/Infinite Space/Mugen Kouro 时，读 [已验证案例](references/infinite-space.md)；不要把它的地址偏移、存档容量或标记值推广到其他游戏。
- Game ID/地区标签相同不保证汉化补丁、修订、运行阶段的地址相同。别人发布的地址只是候选；不要轮流写日/美/欧版地址碰碰运气。
- 金钱等数值先用 `memory_scan` 搜索小端编码，执行一次已知增减，再搜索并求候选交集。区分 HUD 副本、实时字段和保存字段；不能仅凭某地址“像这个数”就确定。
- 图鉴等数组用 `memory_table_read` 检查值分布、步长和边界，对照 UI 已解锁比例。连续编号或大指针值可能不是布尔标记。未知值不要统一覆盖。
- 数据使用安全 `memory_peek`/`memory_poke`，代码使用 `code_peek`/`code_patch`。ARM9 数据视图会跟随 TCM；AR 引擎走 ARM7 总线，二者不是普遍等价的视图。
- 在副本上做最小修改：单字段带 `expected_hex`；数组用新读取的整段 `expected_sha256`，明确 `replace_values`，保留更强标记和间隔内的其他字段。若哈希过期，重新检查原因，不去掉保护条件。若多段写入中途失败，不直接重试，先检查或恢复隔离副本。

## 两种产出

**制作金手指**：先证明地址与效果，再用 `cheat_generate_ar` 生成定长直接写/步长循环。它不会安装或启用代码，也没有自动证明对当前游戏有效。Select 是按住时重复执行，不是上升沿单次；持续值可能破坏动态字段。不会保留“已拥有=2”等更强标记的循环不能冒充安全的全图鉴存档修改。不要承诺普通 `.sav` 会自动继承金手指效果。

**修改普通存档**：修改内存只是中间态。在正确的用户存档栏位中通过游戏保存菜单正常保存，等待完成，再 `backup_export` 导出新 `.sav`。先截图核实效果，再结束核心进程，用新进程仅加载该 ROM + 导出 `.sav`；不加载即时存档、不自动施加补丁、不启用旧金手指。重新进入图鉴或读入剧情，核对目标效果与未请求修改的进度/金钱等。

## 交付

导出工具返回的 `cold_boot_verified: false` 是准确的：只有上述独立冷启动证据才能把交付结果称为持久生效。分别报告内存效果、普通存档持久性、未测试设备/跨区兼容性。

若用户已授权替换原档，先确认 GUI 不在写同一个文件，并比较原档当前哈希和备份哈希；已变化则交付独立副本，不覆盖新进度。保留备份并给出路径。旧 `.mch` 代码只有在确认与本 ROM 不匹配且属于本任务范围时才备份后禁用，不批量清空其他代码。

不把 ROM、个人 `.sav`、即时存档、内存 dump 或本机绝对路径日志提交到仓库。同步 GitHub、变更分支或发 PR 需要用户另行明确要求，不由改存档请求推导。
